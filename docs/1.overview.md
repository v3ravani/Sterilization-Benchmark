

## Title
When Is Binary Serialization Worth the Trade-Off? An End-to-End Workload- and
Network-Aware Study of JSON, Compressed JSON, and Binary Serialization



## Three Formats Compared
JSON — baseline serialization format
JSON + GZIP — compression-based optimization while retaining JSON
MessagePack — binary serialization format


JSON Pipeline

## Pipeline:

Original Data -> Application Data Model -> JSON Serialization -> Payload Measurement ->
Controlled Network -> Receiver -> JSON Deserialization -> Data Validation -> Resource
Measurement -> End-to-End Metrics

## 1. Original Data

Generate the original logical dataset.

Select data model, redundancy level, and target size.

Record original data size.

Keep the original object for validation.


## 2. Application Data Model

Represent the dataset as the application-level object.

Use the same logical data for all three formats.

Data characteristics include structure, redundancy, and payload size.


- JSON Serialization


Convert the application object into JSON.

Measure serialization time.

Record the resulting JSON payload size.


## 4. Payload Measurement

Measure the exact JSON payload size in bytes.

No compression is applied.

JSON is used as the baseline.


## 5. Controlled Network

Send the JSON payload through the controlled network.

Vary bandwidth and network latency.

Measure transmission time.


Network time is approximately:

## T_network = Network Latency + Payload Size / Bandwidth

## 6. Receiver

Receive the complete JSON payload.

Record reception time.

Pass the payload to the JSON deserialization stage.


- JSON Deserialization

Convert the received JSON back into the application object.

Measure deserialization time.


Record CPU and memory usage.


## 8. Data Validation

Compare the reconstructed object with the original object.

Verify that all fields, values, data types, arrays, and nested structures are preserved.

Mark the run valid only if the reconstructed data matches the original.


- End-to-End Latency

JSON total latency:

T_JSON = T_serialization + T_network + T_deserialization

This is the primary performance metric for the JSON baseline.

## 10. Repeated Runs

Run every configuration multiple times.

Record every individual measurement.

Calculate mean, median, p95, standard deviation, and confidence intervals.




JSON + GZIP Pipeline

## Pipeline:

Original Data -> Application Data Model -> JSON Serialization -> GZIP Compression -> Payload
Measurement -> Controlled Network -> Receiver -> GZIP Decompression -> JSON
Deserialization -> Data Validation -> Resource Measurement -> End-to-End Metrics

## 1. Original Data

● Generate the original logical dataset.


● Select data model, redundancy level, and target size.

● Record original data size.

● Keep the original object for validation.


## 2. Application Data Model

● Represent the dataset as the application-level object.

● Use the same logical data used for JSON and MessagePack.

● Keep data structure, redundancy, and target size unchanged.


- JSON Serialization

● Convert the application object into JSON.

● Measure JSON serialization time.

● Record the uncompressed JSON size.


- GZIP Compression

● Compress the serialized JSON using GZIP.

● Measure compression time.

● Record the compressed payload size.

● Calculate compression ratio and payload reduction.


Compression ratio:

● Compression Ratio = Compressed Size / JSON Size

## 5. Payload Measurement

● The compressed GZIP payload is the actual transmitted payload.


● Record exact transmitted size in bytes.

● Use this size for network transmission calculations.


## 6. Controlled Network

● Send the compressed payload through the controlled network.

● Vary bandwidth and network latency.

● Measure transmission time.


Network time is approximately:

## ● T_network = Network Latency + Payload Size / Bandwidth

## 7. Receiver

● Receive the complete GZIP payload.

● Record reception time.

● Pass the payload to the decompression stage.


- GZIP Decompression

● Decompress the received GZIP payload.

● Measure decompression time.

● Recover the original JSON payload.


- JSON Deserialization

● Convert the decompressed JSON back into the application object.

● Measure deserialization time.

● Record CPU and memory usage.



## 10. Data Validation

● Compare the reconstructed object with the original object.

● Verify fields, values, data types, arrays, and nested structures.

● Mark the run valid only if the reconstructed data matches the original.


- End-to-End Latency

JSON + GZIP total latency:

T_GZIP = T_serialization + T_compression + T_network + T_decompression +
## T_deserialization

This includes the additional processing cost of both compression and decompression.

## 12. Repeated Runs

● Run every configuration multiple times.

● Record every individual measurement.

● Calculate mean, median, p95, standard deviation, and confidence intervals.



MessagePack Pipeline

## Pipeline:

Original Data -> Application Data Model -> MessagePack Serialization -> Payload Measurement
-> Controlled Network -> Receiver -> MessagePack Deserialization -> Data Validation ->
Resource Measurement -> End-to-End Metrics

## 1. Original Data

● Generate the original logical dataset.

● Select data model, redundancy level, and target size.


● Record original data size.

● Keeping the original object for validation.


## 2. Application Data Model

● Represent the dataset as the application-level object.

● Use the same logical data used for JSON and JSON + GZIP.

● Keep data structure, redundancy, and target size unchanged.


- MessagePack Serialization

● Convert the application object into MessagePack binary format.

● Measure serialization time.

● Record the resulting MessagePack payload size.


## 4. Payload Measurement

● Measure the exact MessagePack payload size in bytes.

● No additional compression is applied.

● Calculator payload reduction relative to JSON.

● Payload Reduction = 1 - (MessagePack Size / JSON Size)

## 5. Controlled Network

● Send the MessagePack payload through the controlled network.

● Vary bandwidth and network latency.

● Measure transmission time.


● Network time is approximately:


## T_network = Network Latency + Payload Size / Bandwidth

## 6. Receiver

● Receive the complete MessagePack payload.

● Record reception time.

● Pass the payload to MessagePack deserialization.


- MessagePack Deserialization

● Convert the received binary payload back into the application object.

● Measure deserialization time.

● Record CPU and memory usage.


## 8. Data Validation

● Compare the reconstructed object with the original object.

● Verify fields, values, data types, arrays, and nested structures.

● Mark the run valid only if the reconstructed data matches the original.


- End-to-End Latency

MessagePack total latency:

T_MessagePack = T_serialization + T_network + T_deserialization

This measures whether the smaller binary payload compensates for the serialization and
deserialization cost.

## 10. Repeated Runs

● Run every configuration multiple times.

● Record every individual measurement.


● Calculate mean, median, p95, standard deviation, and confidence intervals.





## Metrics

The metrics are divided into the following categories. All metrics from the research design are
retained.

## 1. Serialization Metrics

● Encoding time

● Decoding time

● CPU usage during encoding

● CPU usage during decoding


For JSON + GZIP:

● Compression time

● Decompression time


## 2. Data Metrics

● Payload size

● Compression ratio

● Payload size reduction


Payload reduction:

Payload Reduction = 1 - (Format Payload / JSON Payload)

## 3. Network Metrics


● Network bandwidth

● Network latency

● Transmission time

## ● Throughput


Network time:

## T_network = Network Latency + Payload Size / Bandwidth

## 4. System Metrics

● CPU utilization

● Memory usage


- End-to-End Metrics

● Primary metric:

● Total end-to-end latency


## JSON:

T_JSON = T_encode + T_network + T_decode

## JSON + GZIP:

T_GZIP = T_encode + T_compress + T_network + T_decompress + T_decode

MessagePack:

T_MP = T_encode + T_network + T_decode

## 6. Energy Metrics

● Network energy


● Total energy

## 7. Stability Metrics

## ● Variance

● Standard deviation

## 8. Engineering Metrics

## 9. Trade-off Metrics

● Network savings

● Computational overhead

● End-to-end performance benefit


The main trade-off is:

Network Savings vs Computational Cost


These metrics are used to determine whether reduced transmission cost justifies additional
serialization, compression, decompression, or deserialization overhead.

- Break-Even Metrics

Two primary break-even measurements:

Payload Break-Even

Payload size where switching becomes beneficial.


Network Break-Even

Bandwidth where the network savings become sufficient to compensate for additional
processing cost.
