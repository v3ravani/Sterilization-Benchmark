PROJECT RULES

1. GENERAL
- This project is a research-grade benchmark, not a demo project.
- Focus is on accuracy, reproducibility, and clear comparison.
- No unnecessary features (UI, DB, ML, etc.) in core system.

2. DATA CONSISTENCY
- All formats (JSON, GZIP, MessagePack) must use the SAME dataset.
- No format-specific data manipulation allowed.
- Every run must validate decoded data against original.

4. MEASUREMENT RULES
- Measure:
  - Serialization time
  - Compression / decompression time
  - Network transmission time
  - Deserialization time
  - Total end-to-end latency
  - Payload size
  - CPU and memory usage
- Do not mix measurement with logic.

5. NETWORK CONTROL
- Network conditions must be controlled and reproducible.
- Use predefined profiles (FAST, MODERATE, SLOW, VERY_SLOW).
- Do not hardcode network assumptions.

6. EXPERIMENT INTEGRITY
- Each experiment must be repeatable.
- Multiple runs required for every configuration.
- Store raw results; never overwrite existing data.

7. ANALYSIS RULES
- Use statistical measures (mean, median, p95, std deviation).
- Identify:
  - Payload break-even
  - Network break-even
- Do not make assumptions without measured data.

8. DECISION LOGIC
- Final output must include:
  - Best performing format
  - Relative gain
  - Recommended format
  - Reason (network-bound / CPU-bound)
- Performance winner ≠ final recommendation.

9. CODE QUALITY
- Keep modules small and independent.
- Avoid hardcoding values; use config files.
- Write minimal but meaningful tests.

10. SCOPE CONTROL
